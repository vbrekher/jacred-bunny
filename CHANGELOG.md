# Changelog

## Unreleased — native SQL development

The v1.0.0 production gates remain incomplete. These changes extend the original JacRed .NET service and preserve its API, tracker roster and license; they do not announce a production release.

- Separate root-only read-only archive preparation from UID 1000 export HTTP in the managed image, with immutable helpers, bounded private handoff verification and entrypoint override rejection. Require synthetic protected-volume image acceptance before installer packaging. Actual owned-volume diagnosis confirmed an inventory permission refusal with 20 keys/20 torrents; real export and SQL migration remain unverified.
- Distinguish an occupied export slot from an exhausted three-download budget using fixed 429 reason headers. Force actual TCP backpressure in HTTP acceptance and retry only bounded contention, retaining the exact quota check. This fixes a Linux acceptance race; it does not explain or claim to fix the earlier cloud exporter startup failure.
- Add an administrative read-only legacy source preflight with fixed private-safe phase/error codes, bounded inventory/open checks and cooperative cancellation. It creates no archive and never attests quiescence or production readiness. Actual owned-volume diagnosis remains pending deployment.
- Recover missing historical migration metadata only from exact verified server receipts and pinned source SQL. Publish complete rollback payloads atomically and preserve matching interrupted caches. Five new regression cases and all 230 Python tests pass; actual read-only reconciliation enabled a legacy update. The subsequent cloud export failed its startup check and was compensated with compute stopped; no migration PASS is asserted.
- Add journalled CLI legacy export with source/capability checks, a verified graceful shutdown receipt, streaming original-writer readback, private archive validation and stopped environment compensation. Teach the independent watchdog to reconcile known export identities; ordinary start refuses pending export. Actual local normal shutdown/export/client verification passes; control-plane lifecycle cases are explicitly simulated. Cloud migration and nonempty SQL import remain open.
- Add a separate bounded legacy byte exporter before normal app/boot initialization. It archives original Data/config bytes, Tracks/checkpoints, daily masters, timestamps and SHA256 without registering normal writers. Require the current private admin key, one concurrent transfer, a three-attempt budget and an absolute expiry. Actual local HTTP and 22 archive/two boot cases pass; 1071 .NET and 195 Python tests pass. Owned-volume cloud migration, SQL import and restore remain incomplete.
- Refuse dangling output symlinks and publish private local migration/capture artifacts without overwriting concurrently created files. Explicit SQLite stage replacement remains opt-in. Four regression methods reproduce eight failing baseline cases; all 193 Python tests now pass. Encode read-only SQLite file URIs so reserved path characters cannot redirect reads. This does not establish live migration acceptance.
- Replace permissive certificate callbacks with platform validation in .NET tracker transports and operational Python scripts. The exact TLS image collected two additional SubsPlease records into Bunny SQL, increasing the real staging catalog from 20 to 22. [TLS changes](https://github.com/vbrekher/jacred-bunny/pull/26).
- Pin public announce probes to validated DNS results, disable redirects/proxy/cookies, exclude private passkey URLs and require a matching BEP 15 UDP response. Bound attempts and execution time. These probe changes have source/local transport validation; deployed all-tracker acceptance remains open. [Probe changes](https://github.com/vbrekher/jacred-bunny/pull/27).
- Page administrative SQL snapshot proofs over one read transaction, retaining the existing framed checksum and bucket receipt formats. Reject lost streams, unsafe routing and unconfirmed cleanup. Limit concurrent proofs and retain explicit row and time limits. Local data exceeding the former 8 MiB response cap matches an independent verifier; full deployed large-catalog acceptance remains open.
- Commit large catalog writes over bounded HTTP pages inside one transaction, retaining optimistic guards and durable receipts. Remove the former 900-record/1,000-statement/4 MiB overall-write limits; retain per-statement transport bounds. Return the stored revision when the same delivery is retried from a newer snapshot. Local tests cover later-page rollback, stale grouped moves and lost commit responses.
- Read bucket revisions, rows and index metadata through consistent bounded pages. Page receipt metadata without changing its ordinal checksum format. Reject missing pages and count mismatches instead of returning partial results; preserve whole-bucket interfaces and memory limits.
- Deploy the exact paged SQL image to the existing owned MC/Edge pilot and verify snapshot/auth/no-store behavior against the real 22-record catalog. Stop compute after the bounded window; the collector invocation with zero new commits is explicitly not a new write-path PASS.
- Require a configured administrative key on every network, including LAN and localhost, fixing a config-secret disclosure through cross-origin local requests. Keep the explicit keyless legacy LAN mode with browser-origin/fetch-metadata checks. This tightens authentication without removing administrative routes.
- Deploy the hardening image to the existing pilot, compare one real nonempty native result through MC/Edge and verify config-schema key permissions plus unchanged catalog proofs. Retain explicit limits on what the live slice proves.
- Enforce journalled no-store rules on owned staging CDN zones and validate actual authenticated HTTP headers. Preserve digest-pinned payload history across update/rollback and keep staging compute bounded. [CLI policy](https://github.com/vbrekher/jacred-bunny/pull/25).
